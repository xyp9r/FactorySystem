ЭТАП 3 — Бизнес-логика, Безопасность и Валидация
Что нужно понимать:
— Хеширование паролей (bcrypt для хранения паролей в базе).
— JWT (JSON Web Tokens) — авторизация.
— Middleware в ASP.NET Core (перехватчики запросов).
— FluentValidation (библиотека для промышленной проверки входящих данных, чтобы юзер не прислал пустой пароль или отрицательное количество деталей).
⚡️ Практика:

Настроить роли: статус детали может менять только рабочий.
Прикрутить FluentValidation для всех входящих запросов. Настроить глобальный перехватчик ошибок (чтобы сервер возвращал красивый JSON, а не падал).
✅ Готовность двигаться дальше:
— Попытка сделать запрос без токена выдает строго 401 Unauthorized.
— Попытка отправить пустую строку вместо имени детали отбивается красивой ошибкой от FluentValidation.

ЭТАП 4 — Архитектура Мидла (Clean Architecture)
Что нужно понимать:
— Разделение слоев (Layered Architecture).
— DTO (Data Transfer Objects) — почему нельзя отдавать клиенту сущность из базы данных напрямую.
— Маппинг данных (AutoMapper или ручной маппинг).
⚡️ Практика:


Рефакторинг монолита. Разбить проект на слои: API (контроллеры), Application (бизнес-логика), Infrastructure (БД) и Domain (чистые сущности). Использовать DTO, чтобы скрывать хеш пароля от клиента.
✅ Готовность двигаться дальше:
— Клиент получает только безопасные DTO.
— Твои контроллеры стали "тонкими" (просто вызывают сервисы из слоя Application).
